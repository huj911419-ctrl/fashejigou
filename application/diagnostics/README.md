# USB 硬件诊断

面向独立 `gimbal_bench` 和 `friction_bench` 固件，共用诊断框架，各自报告自己的设备。
默认每 1000 ms 输出一份详细报告。诊断查询不使能电机、不刷新控制命令租约、不修改 PID、不自动清除故障。
摩擦轮固件另有 USB `off/set/pid/ramp` 控制命令，原有语法保持；云台固件不注册这些命令。
新增 [摩擦轮 USB 日志](../friction_bench/USB_LOG.md)：`log 1` 输出故障原因，`log 2` 输出可复制给 AI 的运行数据和每秒摘要；UART VOFA 保持原样。

模块选择见 [`bench_features.h`](../bench_features.h) 和 [逐项验证说明](../../docs/architecture/module-switches.md)。USB、板级诊断和事件记录可分别关闭；状态报告中的 `DISABLED` 表示本次构建主动关闭，不是设备离线。USB=0 时不枚举 CDC，也没有 USB 报告。

## 连接电脑

1. 编译、烧录实际要用的独立固件：`make -f Makefile.gimbal` 或 `make -f Makefile.friction`。它们仍是两套独立固件，不会同时驱动两套机构。
2. 用支持数据传输的 USB 线连接 DM-MC02 板卡原生 USB 与电脑。无需选择调试 UART。
3. 在设备管理器找到新增的 COM 口，使用任意文本串口终端打开，选择 115200、8N1、UTF-8，发送结尾加换行。固件默认持续报告；没有开机横幅也可发 `version` 或 `status`。
4. 先发 `ping`，收到 `[pong]` 说明电脑发送、板端解析和回复这条链路工作。再看 `status` 里的各设备反馈。

USB 使用 STM32 CDC 虚拟串口，115200 是终端设置值，不决定 USB 总线速率，也不会配置 UART5。
手册打印页 5、8、15（PDF 页 7、10、17）确认 USB 全速、BMI088 和 PA11/PA12 引脚；工程使用 OTG_HS 外设的内置全速 PHY，故 `HS` 文件名不代表 480 Mbps 高速。
现有 USB VID:PID 为 `0483:5740`，产品名 `STM32 Virtual ComPort`；这组 VID:PID 并非本板独有，应按插拔新增端口/设备序列号确认。

USB 供电不能证明外部电机已有 24 V。电源行显示的是 GPIO 输出指令，当前没有采样实测电压。
如果主程序在 USB 初始化之前卡住或进入 Error_Handler，USB 无法打印原因，需要使用调试器或已有 RTT；本实现不是上电前故障记录器。

## 电脑端可选脚本

脚本是普通 Python 工具，不依赖本人的绝对路径；可移植到其他电脑。

```powershell
python -m pip install pyserial
python tools/usb_console.py --list
python tools/usb_console.py --port COM7 --log logs/board.txt
```

把 COM7 换成实际端口。在脚本窗口输入下表命令，`exit` 或 Ctrl+C 退出。脚本显示接收时间并追加保存 UTF-8 文本，断开后每秒重连同一端口。
如果 Windows 重分配了 COM 号，重新 `--list` 再启动；脚本不擅自挑选别的串口，不重放断线期间输入的命令。
日志中的电脑时间是接收时间，固件 `uptime_ms` 是板端开机毫秒；两者都不是每个传感器的同步采样时间。

## 命令

| 命令 | 作用 |
| --- | --- |
| `help` / `version` | 固件应用名、构建时间、协议版本、单位、命令表 |
| `ping` | 回复板端开机时间，检查往返通信 |
| `status` | 查询报告；摩擦轮用简短中文，云台沿用原格式；前一份未发完时回复 BUSY，请稍后重试 |
| `status detail` | 仅摩擦轮：手动查询详细中文状态及参数 |
| `status raw` | 查询原始完整字段；云台与 `status` 相同 |
| `events` | 查询 RAM 最近 32 条状态首次观测/变化；记录满后覆盖最旧条目，复位丢失历史 |
| `stream on` / `stream off` | 开启/关闭周期报告，仍可手动查询 |
| `period 5000` | 状态报告周期改为5秒，允许200～10000 ms；摩擦轮默认5000 ms，云台默认1000 ms |
| `log 1` / `log 2` | 仅摩擦轮：故障报告 / AI 运行日志，不改变电机运行状态 |
| `log period 20` | 仅摩擦轮：运行日志周期 20～1000 ms，默认 20 ms |

周期设置仅存在 RAM，不写 Flash；重新开串口保留设置，板卡复位恢复默认。重新枚举或 DTR 改变会开始一个新诊断会话并重新输出横幅。
DTR 不作为发送必需条件，兼容不置 DTR 的串口助手。部分终端只关窗口、不通知设备；此时用 `version` 查询。
CR、LF、CRLF 均可结束命令。最长 79 个可打印 ASCII 字符；非法字节、过长输入、接收丢失或半条命令停顿超过 2 秒，丢弃至下一换行。
本接口使用文本，不能和 VOFA JustFloat 二进制帧混在同一个 CDC 字节流。原有 VOFA 保持独立传输适配接口，串口仍由用户指定。

## 如何判断硬件通不通

| 日志部分 | 证据与含义 |
| --- | --- |
| `board` | CPU 时钟、芯片 UID、RCC 原始复位标志；`reset_sticky` 是自上次清除以来的累计标志 |
| `rtos` | FreeRTOS 剩余/历史最小堆、USB 任务最大轮询间隔；当前没有启用任务栈水位 API |
| `power` | 三路电源控制脚 ODR 高低；`voltage=NOT_MEASURED`，不能据此确认负载供电 |
| `usb` | 枚举状态、DTR/RTS、会话、RX 字节/丢弃、TX 入队/完成、忙和错误计数 |
| `CAN1/2/3` | 外设是否启动、标称位速率、HAL 错误、Bus-off、TEC/REC、LEC、TX 空位/挂起 |
| `DBUS` | UART5 原始字节、有效帧计数、最近帧年龄、通道、开关和键值 |
| `DM-J4310` | 握手阶段、配置 ESC_ID、发现的 MASTER_ID、有效反馈计数、反馈年龄和驱动故障 |
| `yaw` | 控制任务快照新鲜度、应用使能/电机实际 ON、目标/斜坡参考/实测速率、转矩、温度 |
| `yaw_inhibit` | 最近一次控制决定没有允许运行的具体原因，各字段可组合；快照标记 STALE 时不能当作当前结论 |
| `BMI088` | SPI 初始化状态、寄存器配置/检查阶段、采样计数、年龄、温度、三轴加速度/角速度 |
| `attitude` | 静止校准进度、姿态/航向有效性、安装轴确认、四元数、RPY、连续相对 Yaw、陀螺零偏 |
| `F1/F2/F3` | 配置 CAN/ID/方向、反馈在线/过期、RPM、原始电流、温度、PID 分项/参数/输出 |
| `readiness` | 转速达标阶段、逐轮达标掩码；不代表允许供弹，也不能使用过期快照 |
| `console` | 周期、跳过报告、丢弃整行、拒绝输入、排队字节；结尾 `complete=1` 表示本次报告成功入队 |
| `yaw_timing` / `imu_timing` / `friction_timing` | 调用次数、最近/最大调用间隔、超期/同毫秒次数；不是执行耗时或 CPU 占用率 |

事件字段与周期统计的详细含义见 [运行记录说明](../runtime/README.md)。事件只记录到状态变化，不代表每个硬件异常都能被保存；同一故障持续存在不会重复刷满记录。

状态含义严格区分：

- `UNCONFIGURED`：尚未填 ID 等必需配置。以当前配置报告为准，不能据此诊断接线故障。
- `NOT_STARTED` / `NOT_MONITORED` / `NOT_ENABLED`：此固件没有启动、观察或启用该功能，不冒充离线故障。
- `STARTED_NO_LINK_PROOF`：CAN 控制器已经启动，但这不足以证明电机响应；看具体设备有效反馈。
- `NO_BYTES`：遥控 UART 没收到字节；`NO_FRESH_VALID_FRAME`：没有新鲜有效 DBUS 帧，可能协议/格式错误或已断线。
- `NO_FEEDBACK`：从未收到该电机的有效反馈；`STALE`：旧数据已超过对应时限。没有历史样本时，age 数字是开机时间差，需结合 valid/count 看。
- `ONLINE`：最近收到了有效设备数据；电机仍可能处于关闭或故障状态，另看 state/fault/enable。
- `BUS_OFF` / `ERROR_PASSIVE` / `FAULT`：分别是 CAN 总线状态和驱动/算法故障；报告给出原始码和相关提示。

特别注意：`tx_queued` 只代表本地入队，USB `tx_complete` 只代表 USB 传输完成，均不证明目标应用处理了数据。
报告各行来自不同任务的独立一致性快照，不是所有设备同一时刻的原子照片；每个反馈都有年龄。
读取 CAN PSR/ECR 会按芯片规则清除 LEC/CEL 的历史状态，其他底层代码也可能读取，所以 LEC=7 不代表历史上从无错误。
当前位速率按该板未启用额外 CAN 时钟校准分频的配置计算，移植时应核对实际时钟链。

## 云台为什么没有运行

`status` 的 `[yaw_inhibit]` 同时输出 `mask` 和展开后的 0/1 字段。下表数值为十进制位值，输出的 mask 为十六进制。
例如 `mask=0x6 command=1 actuator=1` 表示该轮命令不合格且执行器未就绪，不需要靠猜测 PID 找原因。

| 位值 / 字段 | 这一轮的含义 | 如何继续定位 |
| --- | --- | --- |
| 1 / `config` | 控制配置不合法 | 核对配置范围、单位及初始化结果 |
| 2 / `command` | 命令缺失、无效、过期或时间戳不合格 | 看 DBUS 有效帧、命令年龄与输入状态 |
| 4 / `actuator` | 端口、握手、反馈或驱动状态不允许运行 | 看 CAN、DM 阶段及 fault；已锁定故障按原恢复流程处理 |
| 8 / `timing` | 同毫秒重复调用或调用间隔超过配置上限 | 看 `yaw_timing`；当前上限 10 ms |
| 16 / `rate` | 请求不是有限数或超出允许 rad/s 范围 | 检查命令来源、单位和配置，不是实测速率超限标志 |
| 32 / `switch_off` | 条件合格后执行了关闭分支 | 正常关闭原因；原始开关值另看 DBUS |
| 64 / `rearm` | 需要重新完成有效的 OFF→ON | 原问题消除后，回零并重新切换开关；一直保持 ON 不会自动恢复 |
| 128 / `start_nonzero` | ON 上升沿请求速度不为零 | 摇杆回零后重新 OFF→ON；只回零不会补办这次解锁 |

`mask=0` 只说明应用授权，不证明电机实际 ON；后者看 `yaw` 的电机状态与新鲜反馈。
此行是状态快照，`snapshot=STALE` 时数值只供回溯。各位描述实际执行的判断分支，并不同时列举所有原始输入状态。
原因消失后，保持 ON 可能显示 `rearm`；USB `events` 的 `yaw.inhibit` 能帮助查之前的短暂原因。
历史只有最近 32 条变化，不保证保留每一次异常。

## 故障定位顺序

1. **没有 COM 口**：确认烧录的是新 bench 固件、USB 数据线、板卡接口、电脑设备管理器、程序是否走到 `MX_USB_DEVICE_Init`。不应先改 PID。
2. **有 COM 但无报告**：确认端口无其他程序占用；发换行，再发 `version` / `stream on` / `ping`。查看是否刷错固件或早期任务创建失败。
3. **CAN 报错/电机无反馈**：核对独立电机电源、共地、CAN-H/L、终端电阻、位速率、ID；CAN 初始化成功不等于接线成功。
4. **DBUS 无有效帧**：原始字节为 0 时先查接收机电源、配对、PD2；有字节时再查 DBUS、100k/8E1、反相，不把 SBUS 当 DBUS。
5. **BMI088 报错**：看 SPI、芯片 ID、配置读回、数据更新、范围、设备状态分别是哪一位；不要带故障强行使用旧角度。
6. **IMU 一直 CALIBRATING**：电机保持关闭、板子静止；晃动会重置校准窗口。随云台安装已确认，但轴向未确认，所以默认 `for_control=0`。
7. **运行一段时间后任务/反馈 STALE**：检查任务间隔、命令租约、IO 历史错误和队列溢出，再考虑控制参数。

姿态仍是六轴相对航向，会漂移；连续 Yaw 跨过欧拉奇异区后不能再作为可靠连续角。
目前云台仍为手动速度控制，没有因为增加日志而加入角度保持或自动稳定。

## 分层和移植

```text
应用快照 ──> gimbal_diagnostics / friction_diagnostics
                  │
            diagnostics（查询、报告周期、应用命令钩子）
                  │
            text_console（纯 C，实例、队列、组行）
                  │
            usb_console_port（STM32 CDC、IRQ 缓冲）
                  │
            Cube USB Device → 电脑

board_status 单独提供 H723 外设/RTOS 状态；diagnostics_task 单独绑定 FreeRTOS。
```

- 只迁移文本控制台：复制 `module/text_console`，实现 session/read/write 三个回调。`write` 必须在返回成功前复制数据，异步硬件不能借用调用方缓冲。
- 使用别的 MCU/RTOS：替换 `usb_console_port`、`board_status`、任务入口；纯 C 控制台与业务快照报告可保留。
- STM32 当前适配器在 USB 初始化前替换 `USBD_Interface_fops_HS` 回调表；没有修改 Cube 生成文件。移植到不同 ST USB 库需核对接口、类指针、回调生命周期。
- 该 CDC 必须独占，不能同时调用旧 `USBInit`、`CDCInitRxbufferNcallback`、`CDC_Transmit_HS` 或另一套 USB 日志/VOFA。
- 此工程 USB DMA 关闭。移植到 DMA/Cache 路径必须处理缓存一致性和缓冲地址，不能原样宣称可用。
- BSP 的初始化先于 `MX_USB_DEVICE_Init`，后者仍由现有默认任务启动；诊断不抢先初始化 USB，也不手动重复初始化。
- 板端无动态日志分配。控制台 8 KiB TX 环、1 KiB RX 环，TX 持有 128 B 私有缓冲直到传输完成。USB 任务栈 1024 个 32 位字（4 KiB），低于控制和 IMU 任务优先级。
- 每次轮询最多处理 64 B RX、2 条命令和 128 B TX；IRQ 不格式化输出。前一份报告未排空时跳过新周期报告并计数，不累积无限日志。
- 新会话先输出横幅/初始报告，再处理电脑命令；已经提交给 USB 的一包无法靠软件队列撤回，重开串口时按新的报告头识别会话。
- CDC 生命周期检查和发送提交用一次短临界区防止拔线释放类对象；不等待发送完成。必须上板测量最坏临界区、任务耗时和栈余量，离线测试不证明实时裕量。
- 周期报告采用可读的整数单位：`mrad_s/1000` 为 rad/s，`mm_s2/1000` 为 m/s²，`cC/100` 为摄氏度，`ppm/1e6` 为四元数，`urad_s/1e6` 为 rad/s。无效标志下的历史数值仅供排查。

## 验证边界

`tests/diagnostics/` 直接编译实际控制台、CDC 适配器和两套报告，覆盖未枚举、NULL 类对象、异步 TX 缓冲、发送忙、RX 溢出、分包/非法输入、时间回绕、重连、命令白名单、长报告和过期反馈。
HAL/USB/设备快照在主机测试中由桩提供，并非真实 USB 枚举、电机或传感器验证。
使用 `tests/verify_offline.py` 可一次运行全部测试，成功后删除它创建的临时构建目录；测试源不进入固件构建清单，保留它们不会增加板端体积。
上板后仍需实际检查 COM 枚举/拔插、`ping` 往返、持续收发、逐个硬件反馈、CPU/内存和任务实时性；本轮没有连接实物测试。
