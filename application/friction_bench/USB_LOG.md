# 摩擦轮 USB 故障诊断与 AI 运行日志

USB 电机命令仍为 `off`、`set MASK RPM1 RPM2 RPM3`、`pid WHEEL KP KI KD LIMIT`、`ramp RPM_S`。
UART10 的 VOFA 通道、协议、使能开关和发送周期保持原样。本功能只增加 USB 文本输出。
串口助手选择 **UTF-8**，开启接收保存或复制原始文本；命令以 CR/LF/CRLF 结束。

摩擦轮新增 [临时 DT7/DR16 遥控](REMOTE.md)，默认来源为 REMOTE。
继续用 USB `set` 验证时先发 `source usb`，再 `off` → 原来的周期 `set`。
使用遥控采集时不需要循环发送 USB `set`，保留同样的日志设置与采集时长。

## 两种模式

在 `application/bench_features.h` 设置默认值，重新编译烧录：

```c
#define BENCH_FRICTION_USB_LOG_MODE 1  /* 1=故障诊断；2=AI 运行日志 */
```

也可以直接发送 USB 命令，无需重新烧录：

| 命令 | 用途 |
| --- | --- |
| `log 1` | 简报：控制方式、停机原因/操作、三轮目标/实际RPM；默认每5000ms一份 |
| `log 2` | 周期输出版本化运行日志，默认 20ms（目标 50Hz） |
| `log period 50` | 运行日志周期改为 50ms，允许 20～1000ms；不改变故障报告周期 |
| `stream on` / `stream off` | 开启/暂停当前模式的周期输出；电机命令继续可用 |
| `period 10000` | 故障报告改为每 10 秒一份，允许 200～10000ms；不改变 AI 日志周期 |
| `status` | 两种模式都可查询一份简报，不必等自动输出 |
| `status detail` | 按需查询详细中文：遥控、斜坡、温度、反馈年龄、PID、CAN和USB |
| `status raw` | 手动查询旧版原始完整字段，便于深入排查 |
| `events` | 查询最近状态变化，帮助回看短暂故障 |

模式/周期只保存在 RAM，复位恢复编译默认；USB 会话重连保留运行时设置并重新输出配置。
`log`、`status`、`events`、波形输出都不会续期运行命令、使能电机或清除故障。
`stream off` 只是停日志。停止电机要先停止循环发送 `set`，再发 `off`。

## 方便阅读的故障报告

默认每 5 秒报告一次；连接 USB 时也会先报告一次。想安静地逐项检查可发 `stream off`，再发 `status` 查询。
简报用空行、编号和短分隔线隔开，不反复打印参数、解释和帮助。原始报告的`complete=1`只表示报告完整入队，不表示硬件正常。

先看“当前结论与处理方法”：区分正常停止、遥控未解锁、命令过期、哪只轮缺反馈、温度保护、控制任务过期及 CAN 输出失败，并给出恢复步骤。
默认只显示控制来源及每轮目标/实际RPM。`status detail`再显示S1/S2、档位、斜坡给定、温度、反馈年龄和PID小数。
缺失反馈不会写成 0 RPM；过期快照标为旧记录。软件使能只代表最近控制决定，实际转动看有效速度反馈。
输出与电流反馈保留 C620 原始单位，不当作安培；电源电压没有实测，不能宣布供电正常。

`status raw` 保留板级外设、RTOS、邮箱、掩码、原始缩放参数和停机原因等全部旧字段。
中文报告位于 `friction_status_text.c`，通用诊断框架只提供只读回调；不在 USB 任务里计算 PID、发送电机电流或解锁控制。

中文按完整UTF-8字符发送，USB含非ASCII字节的发送块不超过63字节，环形缓冲跨界也不会切断字符；纯ASCII CSV仍可每次发送128字节。串口助手继续选择UTF-8。电脑接收事件仍可能自行拆分数据，正确的接收软件需要保留跨次读取的半个字符；板端分包测试不能替代实机显示验证。

## 为什么点击后没转

`[OK] ... QUEUED` 表示输入已排队，不代表电机任务已经执行或参数已经生效。
`FRCMD` 记录收到的原始摩擦轮命令、板端接收/解析时间、递增编号和处理结果。
没有对应的 `FRCMD` 时，先查是否发了换行、串口连接、非法输入和 USB RX 计数。

拒绝原因直接区分 `SYNTAX`、`RANGE`、`WRONG_SOURCE`、`REARM_REQUIRED`、`BUSY`、`STALE`、`UNAVAILABLE`。
已接收但仍停用时，普通 `status` 用中文说明；`status raw` 的 `[friction_why]` 与 `[friction_gate]` 保留原始区分：

- 初始化失败/模块关闭/任务快照过期；
- 没有运行命令、250ms 租约过期、请求关闭轮、目标越界；
- 哪只运行所需轮没有反馈或反馈过期；
- 温度、调度间隔、CAN 输出失败；
- 当前原因消失但历史故障仍锁定，需要 `off` → 新 `set`；
- 已使能但零速目标、参考仍在爬升、当前输出触限。

`active_fault` 是该次电机控制的原因；`fault` 还保留历史锁定位。
查询时的控制来源/邮箱状态可能比电机快照更新，不能用它们认定物理输出。
“ENABLED”只证明软件允许输出；“OUTPUT_LIMIT”只描述该采样点，不自动认定机械堵转。

## 一次完整采集

1. 使用 USB 控制时先发送 `source usb`。停止循环运行命令，发送 `off`，用 `status` 确认停用。
2. 发送 `log 2`、`log period 20`、`stream on`，开始保存 USB 接收文本。
3. 用原串口助手每 **100ms** 重复发送当前 `set` 命令。只发一次会在 250ms 超时后停用。
4. 记录启动过程、稳速至少 30 秒、变速过程。单轮通过后再测三轮；换参数时保留整个过程。
5. 停止重复发送，发送 `off`；继续记录至少 1 秒，让日志包含停机结果。
6. 发送 `stream off`，复制包含完整 `FRMETA ... FRMETA_END` 和 `FS ... FE` 的片段给 AI。

例：`set 1 500 0 0` 仅测 F1；`set 2 0 500 0` 测 F2；`set 4 0 0 500` 测 F3。
三轮命令仍为 `set 7 500 500 500`。RPM 是电机转子 RPM，实际轮面线速度还需传动比和直径。
板端日志不会自动提高目标、修改 PID、取消超时保护或调用 AI 服务。

## 日志字段与单位

每条记录独占一行。协议版本为 `schema=1`；不要只复制数值行而丢失配置头。
第一次输出、新 USB 会话、实际应用的参数修订变化，以及每隔 5 秒，都会重新输出配置头。
编译时间是固件标识，`sample_ms`/`emit_ms` 是 uint32 板端开机毫秒，会回绕；电脑接收时间不是采样时间。

| 记录前缀 | 含义 |
| --- | --- |
| `FRMETA` / `FRMETA_END` | 格式版本、USB 会话、构建时间、日志周期、参数修订及配置头是否完整入队 |
| `FRUNITS` / `FRCONTEXT` | 转子 RPM、PID 单位、未知传动/弹速/供电信息、RAM 参数边界 |
| `FRCTRL` | 控制策略版本；`speed_pid_conditional_v1` 使用条件积分抑制向饱和方向继续积累，不能只按 PID 数值混合不同策略的数据 |
| `FRLIMIT` / `FRREADY` / `FRFAULT` / `FRPHASE` | 控制限制、READY 门槛、故障位和阶段的解释 |
| `FRTUNE` | 在线增益与斜坡上限；每轮编译限流上限另见 FRPID |
| `FRREMOTE` / `FRRC` | 遥控映射/超时/上限与帧时间、开关、重新解锁、目标、接收错误；原始时间不会由日志刷新 |
| `FRSOURCE` | 显式 USB 来源切换结果；只是输入排队确认 |
| `FRPID` | 每轮 CAN/ID/方向、当前实际应用的 PID/限流、编译限流上限 |
| `FRBOARD` / `FRCAN` | 配置头生成时的板卡/CAN 观测；各外设并非与电机同一时刻采样 |
| `FRSCHEMA` | 后续记录字段按位置排列的名称，AI 应严格按此解析 |
| `FRCMD,编号,时间,结果,原始命令` | USB 控制/调参输入；`QUEUED` 不等于执行确认 |
| `FS` | 电机快照编号/时间/新鲜度、命令年龄、故障、掩码、READY、参数版本、已消费命令代数、重解锁状态 |
| `FM` | 查询时的来源/邮箱/初始化/待应用参数信息，可能比 `FS` 更新 |
| `FT` | 调用次数、最近/最大调用间隔、超期/同毫秒次数；用于追查短暂调度异常，不是执行耗时 |
| `FW` | 一只轮的反馈有效性/年龄/温度、目标/参考/实际转速、两种误差、输出/电流、PID 分项、触限与数值有效性 |
| `FE` | 帧末尾编号、完整入队标记、累计跳过/丢行/忙次数及两次发帧时间间隔 |
| `FAS` / `FA` / `FAS_END` | 约每秒一组统计摘要；目标/掩码/故障/参数版本变化时提前结束，避免混算 |

`mrpm / 1000 = RPM`；`kp_u / 1e6 = Kp`，`ki_u / 1e6 = Ki`，`kd_n / 1e9 = Kd`。
固定点输出四舍五入到声明的单位；`out_raw` 是控制器输出快照，不是电调接收确认或电源实测电流。
PID 误差单位为 deg/s，所以 `PID误差 = (ref_rpm - actual_rpm) × 6`；积分/微分的时间单位为秒。
`track_mrpm = ref - actual`，`final_mrpm = target - actual`。
`out_raw` 与 P/I/D 已按逻辑方向归一；`iq_raw` 保留物理反馈符号，`iq_logical_raw` 按方向归一。
这些电流字段是 C620 原始控制/反馈单位，不能当作电源输入安培数。

`FW.en` 是这只轮的软件使能；`valid=1` 只表示收到过反馈，必须再查反馈年龄/在线掩码/快照新鲜度。
`finite=0` 时数值不能参与验收；非有限数打印为 0 是传输占位。
`clip=1` 表示整数输出发生饱和，数值仅供故障定位。
`sat=1` 表示当前输出达到实际限流附近，不代表持续触限；需结合采样时间统计。

输出在低优先级 USB 任务中格式化，不在电机任务或中断打印。
USB 有积压时跳过新的周期帧，不等待发送完成；因此 20ms 是目标周期，不保证实际 50Hz。
AI 必须同时检查时间间隔、`FE` 的跳过/丢弃计数、`FS` 快照新鲜度和完整性。
`complete=1` 只证明当时完整加入板端发送队列；电脑应收到同编号 FS、FM、FT、三条 FW 和 FE 才能认为收到完整帧。
主机断线、复位、截断复制都可能让接收片段不完整；缺数据不能自动判定通过。
日志是 1ms 控制循环的降采样观测，可能遗漏快速峰值；短于采样间隔的超调/恢复不能精确量测。

每秒摘要按轮给出有效样本数、稳态样本数、误差带内数、触限数、转速极值、
最大跟踪误差、稳态误差均值/RMS/极值、最大输出和最高温度。
`steady_n` 只统计参考到位后的合格反馈；`in_band_n / steady_n` 是稳态样本合格比例。
`sat_n / valid_n` 是合格运行样本的触限比例，不能当成精确时间比例。
`valid_n=0` 或 `steady_n=0` 的零数值表示不可计算，不能判定误差为零或验收通过。
重复电机快照、过期/无效/截断数值、停用和故障样本不进入合格运行统计。
窗口还给出总观察帧数与最大时间间隔；缺失期间的性能未知。

长时间稳速可复制完整配置头和 `FAS/FA/FAS_END` 摘要，减少粘贴长度；
启动、变速、掉速恢复另附原始 `FS/FM/FT/FW/FE`，每段建议 3～5 秒。
统计摘要无法代替完整瞬态波形；切换模式会重新开始统计窗口。

## 可直接交给 AI 的分析要求

把下段要求和日志一起复制：

```text
这是 RoboMaster 三轮摩擦轮运行日志，请按 FRSCHEMA 和 FRUNITS 解析。
先检查会话/复位、参数修订、完整帧、跳过计数、采样间隔、数值与反馈新鲜度。
按每轮、目标档位、参数修订拆分，先判断不转是否由命令超时、来源、重解锁、
离线、温度、调度、驱动或初始化引起，不要用改 PID 处理这些故障。
合格运行段中：加速时比较 actual/ref，参考到位后比较 actual/target。
给出稳态误差范围/均值、误差带内样本占比、振荡证据、超调、参考到位后的
稳定时间、输出触限持续时间、温升，以及三轮分别是否通过。
把“已证明”“疑似”“数据不足”分开；间断处不要插值虚构峰值或故障恢复时间。
若有调参依据，一次只建议一个小改动，给出沿用现有 pid/ramp 命令的建议、
理由和复测步骤；当前 Kp/Ki 使用 deg/s，时间单位秒，不能直接套 RPM 增益。
没有弹速、供弹时间、传动比、轮径时，不判定发射性能或连发恢复合格。
```

这个日志完成 AI 分析所需的数据采集；自动验收结论应基于完整实机记录。
未来自动写参/自动运行试验仍需单独实现控制客户端及反馈确认，本模块不假装已经完成。

## 验证

主机测试使用真实控制台、日志模块、USB 命令解析与摩擦轮控制任务，硬件反馈/CAN 由测试桩提供。
覆盖模式切换、日志精度/单位、参数应用版本、命令拒绝原因、历史故障锁定、
数值异常、队列拥堵、重连及运行命令 250ms 边界。
主机/编译验证不代替实际 USB 吞吐、RTOS 调度、栈余量和电机性能验收。

## 六档遥控记录

启动默认REMOTE。USB `set`之前先 `source usb`、`off`；遥控启动/恢复需要S1停止再选运行组，摇杆不参与控制。

原FRRC记录列顺序不变，其摇杆值仅供观察。新增FRGEARCFG配置行和可选FRGEAR观察行，不改变FS/FW或VOFA通道：

`FRGEAR,seq,rc_sample_ms,online,group,gear,selected_rpm,target_rpm,previous_gear,last_change_rx_ms,changes`

组0/1/2为停止/低速/高速，档0为停止、1..6为运行档。selected_rpm为开关选择值，即使未解锁也可能非零；target_rpm为遥控生成的目标，实际运行仍须看FM来源、FS使能/故障与FW反馈。last_change_rx_ms使用接收时间；previous_gear只保留最新转换的旧档，changes是累计转换数，采样缺口可能漏掉中间转换。
