# 三摩擦轮 VOFA 调试使用说明

完整参数包导出/导入核心仍在工程中；当前调试配置将 USB CDC 作为摩擦轮控制和调参入口，UART10 只发送 VOFA 波形。原有 44 通道波形格式不变；参数只改 RAM，重启恢复编译默认值。

固件适配已经加入 `Makefile.friction`。通用协议在 `module/vofa/`，本目录负责电机业务映射。
`friction_debug_port.c` 已绑定 UART10 异步发送；UART10 不接收控制命令，USB CDC 负责发送 `set`、`pid`、`ramp` 和 `off`。
默认 ID 仍为 0，必须由用户填好三个 C620 ID 才能控制电机。没有自动启转。

## VOFA 设置与连接

1. 使用 VOFA 连接 UART10，115200、8N1。
2. 选择 **JustFloat** 数据引擎，将接收的数据通道绑定到波形控件。
3. UART10 只接收波形，不向它发送命令；摩擦轮命令从 USB CDC 文本串口发送。
4. 二进制接收区按官方建议选十六进制。RTT 日志走调试器，不混入 UART10。

当前输出固定 **44 通道、180 字节/帧、默认 50 Hz**，约 9000 字节/秒。
UART 8N1 至少消耗 90000 bit/s；115200 下有余量但需实测队列和系统负载。
200 Hz 约 360000 bit/s，需要更高波特率；500 Hz 约 900000 bit/s。
不要只提高采样率而忽略实际端口吞吐，TX 忙丢弃整帧并计数，不阻塞电机任务。

诊断任务约每 1 ms 轮询，输出频率可调 1..500 Hz（周期 1000..2 ms，整数）。
输出是控制任务最新的完整快照，**没有缓存每个 1 ms 样本，也不是频谱/高速瞬态采集器**。
若存在丢帧或任务延迟，上位机按样本序号/时间判断，不能假定每帧间隔完全相等。

## 波形通道（0 起编号）

| 通道 | 内容 |
| --- | --- |
| 0、1、2、3 | 最新回执序号、结果码、参数/操作 ID、读回值或请求值 |
| 4 | 控制快照时间 ms，模 65536，约 65.5 秒回绕 |
| 5 | 控制样本序号，模 65536，可判断抽样间距 |
| 6 | 故障位，解释见 README.md |
| 7、8 | 在线掩码、实际使能掩码（1/2/4 对应三个轮子） |
| 9 | 最近**已生效的 PID/斜坡事务**序号（不是运行命令序号） |
| 10 | TX 整帧丢弃累计数，float 大计数时可能丧失整数精度 |
| 11 | 控制任务实际步长 ms |
| 42 | 运行阶段：0停止、1升速、2三轮就绪、3掉速恢复、4故障、5台架测试 |
| 43 | 各轮就绪掩码，1/2/4 对应 F1/F2/F3；不能单凭该值判断整组工作就绪 |

| 内容 | F1 | F2 | F3 |
| --- | --- | --- | --- |
| 最终目标 rpm | 12 | 22 | 32 |
| 经过斜坡后的给定 rpm | 13 | 23 | 33 |
| 实际 rpm | 14 | 24 | 34 |
| 跟踪误差：给定−实际 rpm | 15 | 25 | 35 |
| PID 输出电流指令 | 16 | 26 | 36 |
| 电流反馈 | 17 | 27 | 37 |
| P 分量 | 18 | 28 | 38 |
| I 分量 | 19 | 29 | 39 |
| D 分量 | 20 | 30 | 40 |
| 温度 °C | 21 | 31 | 41 |

原有 0..41 通道保持含义不变，42/43 为追加通道。
就绪规则、阈值和业务接口见 [READINESS.md](READINESS.md)。
协议编号集中在 `friction_debug_protocol.h`，修改映射时同步更新此表。

先在一幅图叠加 12/13/14；另一幅图显示 16/17/18/19，避免转速和电流混用同一纵轴。
给定和反馈均是电机转子 rpm，没有减速比换算。所有电流通道是 C620 原始量，不是 A；
输出、P/I/D、电流反馈均转换到该轮逻辑方向。输出在停机/驱动故障时显示 0，
表示软件命令，不证明 CAN 报文已经到达电调。P+I+D 是限幅前值，未必等于限幅后输出。
驱动反馈转速经过原有低通滤波；显示的不是未滤波速度。判断反馈是否有效要同时看在线掩码。

## USB 调参命令

USB CDC 文本命令必须以真实换行结束：

```text
off
set 1 200 0 0
set 2 0 200 0
set 4 0 0 200
set 7 200 200 200
pid 1 0.6 0.05 0 800
pid 2 0.6 0.05 0 800
pid 3 0.6 0.05 0 800
ramp 300
```

`set` 的掩码为 1/2/4/7，目标单位是电机转子 rpm；使能运行时必须每 50 ms 左右重复发送完整 `set`，超过 250 ms 未收到新命令会停机。`pid <轮号> <Kp> <Ki> <Kd> <电流限幅>` 只修改指定轮，电流限幅是 C620 原始命令单位。`ramp` 的单位是 rpm/s。

USB 返回 `queued` 只表示调参事务已排队；看到 UART10 的 P/I/D 变化，或看到通道 9 的生效序号更新后，才继续下一项。

## 在线参数表

VOFA 协议的 `get/set/call` 仍由通用模块支持，但当前 UART10 是只输出端口，不能用它接收这些命令；本阶段使用上面的 USB 文本命令。

| 参数 | ID | 允许值 |
| --- | --- | --- |
| 三轮共用斜坡 rpm/s | 1 | 1..2000 |
| 波形发送周期 ms | 2 | 2..1000，整数；此项同步生效，回执 0 |
| 转速上限 rpm | 3 | 只读，默认 1000；上位机不能放宽 |
| F1 Kp / Ki / Kd / 电流限幅 | 10 / 11 / 12 / 13 | 见下文 |
| F2 Kp / Ki / Kd / 电流限幅 | 20 / 21 / 22 / 23 | 同上 |
| F3 Kp / Ki / Kd / 电流限幅 | 30 / 31 / 32 / 33 | 同上 |

Kp 0..100，Ki 0..1000，Kd 0..1；这些是输入校验边界，不是推荐调参范围。
电流限幅允许 1..该轮编译时 `current_limit`，默认最大 1500；不能用串口突破这个上限。
上限定义在 `friction_config.h`，更改硬件试验范围时应主动修改配置并重新编译。
**增益误差单位是度/秒，不是 rpm**，I 使用秒积分，D 使用每秒变化率，不能直接照抄别人的数值。
初始 Kd=0；在线可以修改 Kd，但建议先调好 PI。

所有 PID/斜坡修改以整组事务交给电机任务，回执结果码 **1** 只表示排队。
等通道 9 等于该次序号，或者 get 读回新值，才代表生效。忙时返回 **5**，未覆盖旧事务。
电机 ID 未填写返回 **6**。非法参数返回 **3** 且不修改参数；语法错误会请求停机。
每次只有一项事务在途；上位机应等待确认再发送下一项，避免连续多个 set 仅第一条被接收。

运行中改参数时保留并限幅 Iout；Ki 改为 0 会清除 Iout，便于纯 P 试验。
Kp/Kd 改变仍可能导致输出阶跃，不保证无扰切换。停止后 PID 动态状态清空。
本应用启用 `PID_Continuous`：误差恰为零仍计算并保留积分维持力矩，其他应用未启用此选项。
参数只存 RAM，重启恢复配置默认值，没有隐式写 Flash。

## 操作命令与实例

`call 序号 操作ID 参数...`，操作如下：

| 操作 ID | 参数 | 意义 |
| --- | --- | --- |
| 1 | 无 | 关闭全部电机，零电流滑行 |
| 2 | MASK RPM1 RPM2 RPM3 | 一次提交完整运行命令，mask=1/2/4/7 单轮或全部，0 为关闭 |
| 3 | WHEEL Kp Ki Kd LIMIT | 原子修改指定轮子整组 PID 与限幅，WHEEL=1/2/3 |

以下每行是单独发送示例，不要一次粘贴执行整段。数值仅是说明协议的台架初值。

```text
call 1 1
get 2 10
call 3 3 1 0.5 0 0 1000
get 4 11
call 5 2 1 200 0 0
set 6 10 0.6
get 7 10
call 8 1
```

依次：关闭 → 查 F1 Kp → 提交 F1 纯 P 参数组 → 确认 Ki → 单轮 200 rpm → 修改 Kp → 回读 → 关闭。
停止后确认通道 8 为 0，再启动；修改 PID 后确认通道 9/读回值，再继续下一次修改。

**运行命令需要循环发送**（例如每 50 ms 发送一次 `call 5 2 1 200 0 0`，允许同一序号重复）。
默认 250 ms 未收到新的完整运行命令即故障停机。查询、改 PID、波形发送均不续期。
循环发送器只循环 RUN 命令，不要把整段调参指令循环发送。
停机先关闭上位机循环发送，再发 OFF；否则后续 RUN 仍可能成为新的启动请求。
不要把 OFF 和 RUN 放在同一批发送：关闭有优先权，同周期已排队的 RUN 会被丢弃。

回执只保留最新一条，循环 RUN 会覆盖 get/set 回执。
调参时安排命令间距，等一次回执再继续；运行中可以使用通道 9 的持续生效序号确认 PID 事务。
get 查询应安排在两次 RUN 之间并留出至少一个波形周期，不要长时间暂停运行心跳。

端口绑定 RX 后，RTT 的运行指令被忽略，避免两个控制源互相覆盖；RTT `off` 仍有效。
未绑定端口时原 RTT 调试照常可用。故障恢复仍需关闭和新的运行命令，不自动重启。
