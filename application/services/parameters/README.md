# 参数管理：先保存调好的值，再逐步接入掉电保存

现在完成的是摩擦轮的完整参数包。云台仍保持独立工程；后续云台参数可以复用存储核心，但应定义自己的参数格式和应用入口。

## 从哪里读代码

| 文件 | 负责什么 |
| --- | --- |
| `friction_profile.c/.h` | 把 13 个值编码成固定格式，检查版本、单位、CRC 和数值；不依赖串口或控制板 |
| `friction_profile_service.c/.h` | 接收导入事务、冻结导出快照、判断超时，向摩擦轮任务排队 |
| `../friction_bench/friction.c` | 检查停用与当前修订号，由唯一电机任务应用整组参数并发布结果 |
| `../../tools/friction_profiles.py` | 电脑上的 JSON 文件与 VOFA 通信工具 |
| `../../module/system/parameter_store/` | 可复用的双槽存储核心，暂未接入真实 Flash |

最简单的理解：电脑先准备完整文件；固件先收齐并检查，最后让电机任务一次应用。不能收到一个值就立刻改一个 PID。

## 三个不同结果

- **文件已保存**：电脑上有 JSON；不代表板端修改了参数。
- **QUEUED → APPLIED**：从排队到电机任务已应用，改变的是 RAM。确认 APPLIED 后，电脑再次导出并核对全量参数。
- **掉电保存**：需要实际 Flash 地址、擦除区域、驱动及启动加载策略。当前未绑定，`get ... 109` 返回 0，USB 也显示 `storage=UNBOUND`。本次没有自动保存、自动加载或改变 linker 分区。

调试串口仍留空，由用户后续指定。USB CDC 继续只读输出诊断，不能向它发送这里的二进制调参协议。详细命令见 [电脑工具说明](../../../tools/FRICTION_PROFILES.md)。

## 当前导入规则

1. `BEGIN` 时要求应用输出已停用，没有待执行 RUN 和其他参数事务；不要求轮子物理转速已经归零。
2. 一次暂存 13 项：斜坡 RPM/s，以及每个轮子的 Kp、Ki、Kd、电流限幅。PID 误差单位为电机 deg/s，I/D 时间单位为秒，电流为 C620 原始指令值。
3. `COMMIT` 再次检查参数完整性、CRC、当前硬件配置的限幅、停止状态和完整 32 位修订号；不允许旧参数覆盖后来调好的值。
4. 提交排队后，到电机任务应用并发布快照之前，非零启动请求被阻止；STOP 一直可用。电机任务仍会自己检查停用状态。
5. 每次真正应用参数，修订号增加，包括原来的逐项调参。没有使能命令、目标转速、CAN ID、积分状态写入参数包。

导入和冻结导出各有 30 秒总有效期，查询不续期。参数不全或 CRC 错误时仍处于暂存状态，可以在原期限内修正或 ABORT。已经排队不能 ABORT；通信中断不能推断为“确定没有生效”，应重新查询当前参数。

一次只允许一个通信客户端，一条命令收到回执再发下一条。BEGIN 的序号作为本次 token；随后每条命令用新序号，并携带 token。紧接着复用上次 BEGIN token 会返回 BUSY。重启/更换客户端时清空旧接收缓存，不重放旧事务。协议不是可跨重启可靠投递的消息队列。

`BENCH_ENABLE_PARAMETERS=0` 关闭新参数包操作；原有逐项 VOFA 调参仍可使用。`BENCH_ENABLE_VOFA=0` 则完全停用该通信通道。模块开关在 `../bench_features.h`。

冻结快照中的修订号低/高字（106/107）来自同一次读取；实时低/高字（114/115）是分别查询的诊断信息，可能跨更新，不能拼接后用于一致性判断。

## 以后移植存储

`ParameterStore` 只认识字节，不认识 PID 和电机。移植时实现同步 `read/program/erase` 三个回调，各槽必须处于不同的物理擦除区域。先用 `FrictionProfileEncode` 得到 72 字节，再作为负载保存；读出后必须依次通过 Decode、范围校验和上述停止/排队入口，禁止直接覆盖控制器内存。

存储工作应由单独的低优先级所有者执行，不能放进电机任务或中断。两个槽、读回及提交标记减少写入中断造成的数据丢失，但实板的掉电、缓存和擦除影响仍需要验证。详见 [存储适配契约](../../../module/system/parameter_store/README.md)。

## 验证入口

统一运行 `tests/verify_offline.py`，包括真实应用代码配合模拟 CAN 的导入测试、纯协议边界测试、存储写入中断测试，以及电脑工具的离线测试。测试源码与固件分开，不进入 ARM 业务固件；可以删除测试构建产物而保留测试源码。
