# 摩擦轮就绪与运行状态

这一层只回答“摩擦轮速度是否准备好”，供之后的发射协调模块使用。
它不执行进弹，不推测进弹电机、机构行程或裁判规则，也不将 ready 等同于允许发射。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `module/control/speed_ready/speed_ready.c/.h` | 可移植单通道误差、连续稳定时间和迟滞判定 |
| `friction_monitor.c/.h` | 三轮结果组合及运行阶段管理，不访问硬件 |
| `friction.c` | 电机任务在完成控制和故障处理后更新 monitor，发布完整快照 |
| `friction_debug_protocol.h` | 集中定义 VOFA 参数 ID、操作 ID 和波形通道 |
| `friction_debug.c` | 将快照映射到 VOFA 波形，调参仍通过邮箱提交 |

## 状态与转移

| 数值 | 状态 | 含义 |
| --- | --- | --- |
| 0 | STOPPED | 全部停止，ready 清除 |
| 1 | SPINUP | 三轮正向工作目标有效，尚未完成就绪判定；也包含变更目标后的重新稳定 |
| 2 | READY | 三轮分别就绪，且全部以正向工作目标使能 |
| 3 | RECOVERING | 本轮目标曾全部就绪，随后有轮子掉出退出误差带或采样不连续，正在恢复 |
| 4 | FAULT | 控制故障或就绪配置错误，全部撤销就绪 |
| 5 | BENCH | 单轮/部分使能，或存在零速、反转、低于工作门槛的测试目标 |

正常三轮流程：STOPPED → SPINUP → READY；掉速：READY → RECOVERING → READY。
故障发生后显示 FAULT，沿用原控制层的故障清除/重新使能流程。
变更任何一轮最终目标或应用 PID/斜坡调参事务后，三轮统一重新判定，不沿用旧 ready。
调参只重置判定，不额外关闭正常运行的电机。

`ready_mask` 的 1/2/4 分别表示各轮独立达到条件；用于单轮调试。
**不能仅用 ready_mask==7 判断工作就绪**：三轮反向测试也可能各自达到负目标。
业务应读取 `readiness.all_ready`，它还要求三轮全部使能、正向工作目标和无控制故障。
各轮目标可以不同，不强制使用相同 rpm。

## 暂定参数

集中在 `friction_config.h` 的 `FRICTION_READY_CONFIG`，目前编译时配置：

- 最低工作目标：100 rpm，防止停转/低速试验被当作发射工作状态。
- 斜坡给定与最终目标差：不超过 1 rpm。
- 进入误差带：`max(10 rpm, 目标绝对值的 2%)`，连续 200 ms。
- 退出误差带：`max(20 rpm, 目标绝对值的 4%)`，超过即撤销。
- 相邻判定间隔：最多 5 ms；重复时间戳或更大的间隔必须重新累计稳定时间。

例如目标 500 rpm，首次就绪要求连续 200 ms 在 490..510 rpm；
已就绪后允许保持在 480..520 rpm，超出后撤销，再回到 490..510 rpm 连续 200 ms 才恢复。
这组数字仅用于当前低速台架，后续需依据机构、出弹恢复和实测弹速调整。

## 将来业务怎样读取

```c
Friction_Telemetry_s snapshot;
FrictionGetTelemetry(&snapshot);

/* 后续协调模块还必须验证快照时效、操作请求、进弹机构及裁判条件。 */
uint8_t wheel_speed_ready = snapshot.readiness.all_ready;
```

`sample_ms` 与 readiness 属于同一控制周期的原子快照；消费者必须检查快照年龄，
不能缓存一次 ready 后长期使用。若电机任务不再运行，旧快照不会自行变为新的故障状态。
停止指令采用异步邮箱，下一个控制周期处理，现有的停止优先和超时保护继续生效。

VOFA 前 42 个通道含义保持不变，追加 42=phase、43=ready_mask；总共 44 通道。
READY 对应 phase=2。打开两个新通道就能观察升速、就绪、掉速恢复和故障。
