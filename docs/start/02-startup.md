# 02 上电以后，程序怎么运行

[项目地图](01-project-map.md) · [文档目录](../README.md)

先在电脑上选择并编译一套应用。构建清单只链接这套应用的 `RobotInit()` 和 `RobotOSTaskInit()`；同名函数不会四份一起运行。

| 顺序 | 实际文件/函数 | 做什么 |
| --- | --- | --- |
| 1 | [启动汇编](../../startup_stm32h723xx.s) | 准备 C 运行环境，再进入 `main()` |
| 2 | [Core/Src/main.c](../../Core/Src/main.c) | 初始化 HAL、时钟和外设，调用所选应用的 `RobotInit()` |
| 3 | [摩擦轮 robot.c](../../application/friction/robot.c) 或 [云台 robot.c](../../application/gimbal/robot.c) | 初始化模块、注册诊断、创建应用任务 |
| 4 | [Core/Src/freertos.c](../../Core/Src/freertos.c) | 创建系统默认任务；调度器启动后该任务按开关初始化 USB |
| 5 | `osKernelStart()` | FreeRTOS 开始调度各个任务 |

## “任务”就是交给调度器运行的函数

在 `robot_task.c` 里找 `xTaskCreate()`：它登记任务入口。再找到那个入口函数，通常能看到 `for (;;)` 循环。

| 固件 | 控制任务 | 其他任务 |
| --- | --- | --- |
| 摩擦轮 | `MotorTask`：每 1 ms 处理遥控、控制并喂看门狗 | 调试任务轮询 VOFA/RTT；USB 诊断任务按设置处理文本/日志 |
| 云台 | `YawTask`：每 2 ms 处理一轮云台并喂看门狗 | IMU 任务每 2 ms 采集/解算；另有 USB 和 RTT 诊断 |

这些是代码设置的目标周期，不是对实物每次执行时间的测量。开关会影响是否创建任务或执行模块；主控制服务保留看门狗刷新。

`vTaskDelayUntil()` 让任务等待下一轮，等待期间 CPU 可以运行其他任务。初始化时调用 `xTaskCreate()`，并不表示立刻在那一行执行完整个任务循环。

## 中断与任务怎样接起来

UART/CAN 收到数据时，中断回调先保存数据，控制任务再取出并处理。命令有原始时间戳，状态通过快照供诊断读取。

| 你看到的操作 | 所属位置 |
| --- | --- |
| 把字节放进接收队列 | 板级 port / 外设回调 |
| 把字节解释成遥控和电机反馈 | 协议与设备组件 |
| 检查请求过期、故障、是否允许输出 | 控制任务及控制核心 |
| 把当前状态显示在电脑上 | 诊断任务 |
