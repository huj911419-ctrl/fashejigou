# 无硬件时，怎样逐层验证这个工程

第一阶段记录日期：2026-09-29。对象是本工程新增的云台 Yaw、三摩擦轮与 VOFA 控制链。
这里的“通过”只指列出的软件契约通过；并非整个旧框架或实机控制效果已经验收。

## 方法：运行真实源码，替换外设边界

测试直接编译生产 `.c` 文件，不另外抄一份控制算法。测试端提供时间、输入字节、反馈帧、
传输返回值，观察真实代码发出的指令、状态和参数回执。

```text
可控遥控/CAN/VOFA 输入、时间、故障
              ↓
真实协议 → 真实状态机/命令邮箱 → 真实控制器/打包代码
              ↓
断言：字节是否正确，是否越界，是否停机，是否需要重新授权
```

云台板级测试进一步编译真实 `bsp/ports/gimbal_port/gimbal_port.c`，调用真实 HAL 回调入口，
用 HAL 替身验证它如何使用外设接口。替身不模拟 STM32 寄存器时序，也不会证明真实中断并发正确。
例如 CAN 取消发送仅是请求，不能把 HAL 返回成功当成报文已在总线上停止。

## 本次验证发现并修复的问题

### Yaw 斜坡的中间结果溢出

`YawRateInit()` 允许有限正数作为速度、加速度上限。边界测试使用 `FLT_MAX` 加速度和合法的
100 ms 时间步，发现旧式 `acceleration * elapsed_ms * 0.001f` 会先乘毫秒而溢出。
满正输入后反向，参考速度出现非有限值；旧实现实际触发了 `isfinite()` 断言失败。

修复为先转换秒：`acceleration * (elapsed_ms * 0.001f)`。
回归用例位于 `tests/robustness/test_control_stress.c`，三个种子均通过。
这不是给实际电机推荐巨大参数；默认配置不会触发该极值。它检查的是通用模块所接受的数值范围。

结构重构阶段还修复了两个已加入测试的问题：

- 摩擦轮未收到命令的初始空闲周期，不能把零初始化邮箱当成用户明确的 OFF。
- 云台出队期间收到新的 IRQ 数据时，使用任务入口旧时间计算数据年龄会发生无符号下溢。

## 怎样运行和删除

统一入口：`tests/verify_offline.py`；具体命令见 [tests/README.md](../../tests/README.md)。

- 临时编译目录在系统临时目录；成功后自动校验所有权并删除。
- 失败保留现场，或显式 `--keep-build` 保留成功现场；报告给出精确路径。
- 每次报告在 `.scratch/offline-verification/<时间-唯一编号>/`；保存源码摘要和 JSON/XML/日志。
- 测试源代码只在 `tests/`。正式固件不添加测试开关、伪造反馈或测试任务。
- 删除报告、主机构建或全部测试工具均不改变正式控制逻辑。建议留测试源码，清理生成物即可。

这套工具也可以随可移植核心迁入另一工程，但实际 HAL 替身和应用组合用例需跟随新端口的接口契约调整。
