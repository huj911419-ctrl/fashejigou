# 控制权核心

这个模块回答两个问题：**现在选中了谁的命令？这一路命令是否获得了运行授权？**
它不解析遥控器、不保存速度或角度目标，也不直接使能电机。电机反馈、控制周期、
输出范围等检查继续由下游控制器负责。`authorized=true` 不等于电机已经开启。

`ControlAuthority_s` 由调用者分配，一个控制任务串行调用它的所有接口。核心只有
标准 C 依赖，没有 HAL、RTOS、动态内存或可变全局状态，可以用于别的工程。

## 选择和授权是两回事

来源为 `REMOTE`（遥控）、`DEBUG`（调试）、`AUTO`（未来自动控制），以及停止选择的
`NONE`。应用通过 `allowed_sources` 明确开放来源，再调用 `Select` 选择其中一路。
这里没有优先级、抢占或自动降级：选中的来源断线后保持原选择，同时撤销授权。
不能因为它断线，就自动接上另一路缓存的目标。

首次选择和每次切换来源后，都需要观察到有效的 **OFF → 新的中立 ON**，才允许运行。
中立含义由业务定义，例如速度命令为零。开始运行后允许离开中立位置，否则无法运动。
ON 时不在中立位置会消耗这次 OFF；随后仅回中仍不能恢复，必须重新 OFF → ON。

切换来源会增加 `epoch`，清空旧输入和 OFF 记录。即使来源名相同，旧 epoch 的输入
也会被拒绝。重复选择当前来源不清空状态、不增加 epoch，也不会续期。

**应用必须在切换时清空来源邮箱，并让后续新输入携带新 epoch。**
不能把旧缓存命令的 epoch 改成当前值再次投递；核心无法识别这种错误的重新标记。
`epoch` 是同一次启动内的本地切换标记，不是网络身份认证或跨重启的会话标记。

## 输入时间与停止

`received_ms` 必须保留原始接收时间。有效期使用 `now_ms - received_ms` 判断，
到达超时时间即过期；轮询、查询和重复提交都不能延长它。超时可按来源分别配置，
每项为 1 到 `INT32_MAX` 毫秒，未开放来源的超时项不使用。

同一 epoch 只接收严格递增的时间戳，使用无符号差值支持 32 位毫秒计数回绕。
重复、倒退或相差半个计数空间的输入不能替换已有输入；`sequence` 仅用于诊断。
相同毫秒内的两个不同输入也不会形成 OFF → ON，适配器应保留这个保守约束。
时间戳和比较间隔应小于 `2^31` 毫秒。未来时间戳被判无效，之后时间追上它也不会
重新消费其 OFF 记录。该输入及其时间戳下界会被丢弃，避免阻止后续真实时间的输入；
恢复仍需要新的有效 OFF，再跟一个新的中立 ON。

`Stop()` 立即撤销授权，并锁存到下一次 `Step()`。之后提交的 ON 或来源切换不能
覆盖该停止。输入的 `stop_requested` 同样锁存；来源和 epoch 必须匹配，重复/旧
输入中的停止标志仍被接受，而它的其他字段不会替换当前输入。
每个新接受的无效输入和 `arm=false` 输入本身也会锁存停止，即使生产者没有显式填写
停止标志。因此同批后来的有效 ON 不能覆盖中途的无效输入。
所以新 OFF 的原因位为 `STOP | SWITCH_OFF`；没有停止标志的重复 OFF 不会反复锁存。

如果一批输入最后是 ON，但中途有停止标志，本周期会停止，之后需要新的 OFF。
如果最后是一个本周期新收到的有效 OFF，可以把这个 OFF 用于下一次 ON 授权。
仅有旧缓存的 OFF 不行；轮询旧 OFF 不能越过故障后的重新授权条件。
生产者合并多条命令时，必须保存中途的停止标志。只提交最终 ON 会丢失历史信息。

## 接入顺序

1. 停止输出时初始化实例，配置允许来源及其有效期。
2. 显式选择来源；切换后清空上游邮箱，向新输入链传递 `status.epoch`。
3. 在控制任务内取出命令，带原始时间戳调用 `Submit`。只有返回 `true` 才替换
   应用层保存的速度/角度目标。`false` 仍可能已锁存一个匹配来源的停止标志。
4. 每个控制周期调用 `Step(now_ms)`，读取状态，向下游提交命令。
5. 未授权的 ON 要作为禁止运行处理。**不要将其伪装成“有效 OFF”**，否则下游的
   OFF → ON 检查会被自动通过。真实 OFF 仍应保留其有效性和原始含义。

一个简化的元数据输入如下；具体速度等目标由应用层单独存储：

```c
ControlAuthorityInput_s input =
{
    .source = CONTROL_SOURCE_REMOTE,
    .epoch = active_input_epoch,
    .received_ms = command.received_ms,
    .sequence = command.sequence,
    .valid = command.valid,
    .arm = command.arm,
    .neutral = command.rate_rad_s == 0.0f,
    .stop_requested = command.stop_requested
};
bool accepted = ControlAuthoritySubmit(&authority, &input);
ControlAuthorityStep(&authority, now_ms);
```

`online` 只表示当前选中的输入有效且未过期；它可以在开关 OFF 时为真。
`reason` 是最近一次判断的原因位，可以组合。0 代表核心授权，其余原因包含配置错误、
未选择、无输入、输入无效、过期、未来时间戳、停止、开关 OFF、需要重新授权和启动不在中立。

## 验证边界

`tests/control_authority/test_control_authority.c` 覆盖启动、非中立使能、显式切换、
旧 epoch、错误来源、重复输入不续期、超时、不自动切换、停止/无效输入合批、故障后旧 OFF、
未来时间戳、时间回绕和实例隔离。这是元数据状态机的主机验证，不代表实际遥控链、
自动控制链或电机已验证，也没有实现云台角度模式或自动瞄准算法。
