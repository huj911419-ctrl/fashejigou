# 双槽参数存储核心

`parameter_store` 负责把一份已经序列化的参数数据保存到两个独立存储槽。它不认识 PID、云台、电机 ID，也不会修改正在运行的控制器。

目前提供的是纯 C 存储协议和离线故障测试，**没有板端 Flash 驱动，也没有分配 STM32 Flash 地址**。编译通过和模拟掉电通过，不代表已经验证真实 Flash 的断电、ECC、缓存或擦写行为。

## 分层和调用

```text
应用：导入配置 → 校验参数范围 → 交给控制任务应用
                ↓ 序列化的参数快照
parameter_store：校验记录 → 写备用槽 → 读回 → 最后提交
                ↓ read / program / erase 回调
适配层：电脑模拟 NOR；以后再接指定存储器
```

- `ParameterStoreInit()` 只复制适配器和配置，不读写存储器。
- `ParameterStoreLoad()` 复制最新、完整、兼容的参数数据；失败时不修改输出缓冲和 `info`。
- `ParameterStoreSave()` 同步保存传入的参数快照；成功后输出代次和所在槽。
- 每个实例有一个调用者，两个槽由它独占；没有全局变量、堆、HAL、RTOS 或内部锁。
- 负载长度固定为初始化时指定的 `1..256` 字节。不得直接保存含填充、指针或平台相关类型的 C 结构体；应用应规定明确的字节序、字段单位和版本。
- `schema_id` 表示应用数据格式及版本。结构改变时使用新的标识并提供明确迁移流程，不能只改长度强行覆盖旧记录。
- 参数保存不代表参数已被控制任务应用；应用仍需分别记录“收到”“校验通过”“已应用”“已保存”。本模块不保存电机使能、运行命令或解锁状态。

## 适配器契约

两个槽至少各有 320 字节，必须分别属于**可独立擦除的区域**。真实器件若一个扇区大于 320 字节，就需要为每槽保留完整扇区；把两个逻辑槽放在同一擦除扇区会破坏恢复保证。

| 回调 | 契约 |
|---|---|
| `read(context, slot, offset, data, size)` | 字节寻址；只有完整读取成功才返回 `true`。当前核心每次读取槽内前 320 字节 |
| `program(...)` | 每次恰好写 32 字节；槽内偏移和源缓冲都对齐 32 字节；每个单元一次擦除周期内只编程一次 |
| `erase(context, slot)` | 擦除该槽所属区域，不能影响另一个槽；擦后字节为 `0xFF` |

这些回调都必须同步完成并在返回前消费或复制数据，不能保留核心传入的指针。`false` 可以意味着部分字节已经改变，核心会按失败处理。物理地址映射、源/目的缓存维护、ECC 错误转换、硬件完成等待及电源条件由适配层负责。读取不可靠时返回失败，不能把失败填成 `0xFF` 假装空白。

保存会进行多次擦写和读回，**不能在中断或 2 ms 电机控制循环内调用**。应用应把已校验的独立参数快照交给存储所有者，并选择不会干扰控制的时机。存储核心自身使用固定大小的栈上工作区：Load 的槽镜像约 640 字节，Save 的镜像和构建区约 960 字节，另有函数调用开销；任务栈需按所用工具链实际测量。

32 字节布局方便后续适配具有这种编程粒度的设备，它不构成对某块 STM32 板卡的兼容认证。真实驱动实现前必须核实器件编程/擦除粒度、链接布局和掉电读错误行为。

## 记录格式 v1

所有多字节整数均为**小端无符号整数**，不是宿主结构体布局。CRC 使用 CRC-32/ISO-HDLC：多项式 `0xEDB88320`（反射形式），初值和最终异或均为 `0xFFFFFFFF`；标准向量 `123456789` 得到 `0xCBF43926`。

| 槽内偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 4 | 魔数，字节 `PST1` |
| 4 | 4 | 存储格式版本，当前为 1 |
| 8 | 4 | 应用 `schema_id` |
| 12 | 4 | 参数字节数，1..256 |
| 16 | 4 | 保存代次 `generation`，初次为 1 |
| 20 | 4 | 实际参数字节的 CRC |
| 24 | 4 | 头部长度，固定 32 |
| 28 | 4 | 头部前 28 字节的 CRC |
| 32 | 256 | 参数区；实际长度之后的字节固定保留为 `0xFF` |
| 288 | 4 | 提交魔数，字节 `DONE` |
| 292 | 4 | 代次副本 |
| 296 | 4 | 头部 CRC 副本 |
| 300 | 4 | 参数 CRC 副本 |
| 304 | 12 | 保留字段，必须为 0 |
| 316 | 4 | 提交单元前 28 字节的 CRC |

CRC 用来发现传输、存储损坏，不能作为防篡改认证；随机损坏存在 CRC 碰撞的理论可能。

## 保存和恢复规则

1. 先读取两个槽。任意槽读取失败，返回 `IO_ERROR`，不擦除、不编程。
2. 确认当前最新记录，选择另一个槽；初次保存选择槽 0。
3. 擦除目标槽，写头部和实际参数涉及的 32 字节单元。
4. 读回目标槽前 320 字节，逐字节确认头部、参数、未用区域，以及仍为空的提交单元。
5. 最后写提交单元，再次完整读回并验证，才返回 `OK`。

一次替换保存期间，先前最新记录所在的槽始终不被擦写。若目标槽损坏或尚未提交，重启后仍可加载旧记录；新记录完整提交后加载新记录。失败返回不保证“新记录不存在”：例如提交完成但最后读回失败，保存返回 `IO_ERROR`，重新读取可能找到新记录，因此不能用返回失败推断代次没有变化。

状态含义：

| 返回值 | 含义与处理 |
|---|---|
| `OK` | 加载成功，或保存后读回验证成功 |
| `EMPTY` | 两个槽的记录区域全为 `0xFF`；可首次保存 |
| `CORRUPT` | 无有效记录且存在非空损坏数据，或保存读回内容不符 |
| `IO_ERROR` | 适配器至少一次操作失败；读取失败不会被当作空槽 |
| `INCOMPATIBLE` | 发现校验成立的未知格式，或完整记录的应用格式/长度不匹配 |
| `AMBIGUOUS` | 两个完整记录的代次关系无法可靠判定 |
| `INVALID_ARGUMENT` | 空指针、未初始化、长度不符等接口错误 |

如果有一个兼容有效槽，另一个是损坏的旧/未提交槽，可以继续使用和替换保存。若两个槽都没有有效记录而又不是全空，本模块不擅自擦除；应用应显示损坏状态，通过单独的、明确的重新初始化流程恢复。这个情况也可能发生在**第一次保存中途断电**，因为此时尚无旧记录可恢复。

任意槽包含校验成立的未知格式，或者完整但 `schema_id`/长度不同的记录，Load 和 Save 都返回 `INCOMPATIBLE`，即使另一个槽可读也不自动替换。迁移或重建存储是应用的显式操作。本核心没有“忽略不兼容并擦除”的选项。

代次按 32 位模运算递增，`0xFFFFFFFF → 0` 合法。两代次的差小于半圈时确定先后；差恰为 `0x80000000` 时返回 `AMBIGUOUS`。代次相同且整个记录完全相同，固定选择槽 0；代次相同而内容不同也返回 `AMBIGUOUS`。正常交替保存的两槽只差一代；不支持外部程序在槽中放入相隔超过半个计数空间而又要求推断真实时间的记录。

## 离线验证

测试入口是 [test_parameter_store.c](../../tests/parameter_store/test_parameter_store.c)。使用字节数组模拟只能把位从 1 写成 0 的 NOR，并检查所有编程调用的 32 字节长度/对齐要求。

- 替换保存和首次保存各遍历 833 个字节边界的断电位置，共 **1666 个位置**；重建实例后只接受完整旧记录、完整新记录，或首次保存尚无有效记录时的空白/损坏状态。
- 逐字节破坏最新记录的 320 个字节，确认恢复到旧记录。
- 校验已知 CRC 向量、最小/最大参数长度、多次保存、代次回绕、相同代次冲突、半圈歧义。
- 模拟任一槽读取失败、保存读回失败、驱动错误地报告编程/擦除成功、错误版本/应用格式/长度。
- 错误返回保留调用者输出；读取失败、不兼容或歧义时确认零擦写。

模拟的是字节边界中断和注入的数据/IO 故障，未证明真实 Flash 在掉电时的任意位变化、ECC 异常和执行阻塞行为。后续硬件测试仍需覆盖这些条件。
