# 摩擦轮参数文件与电脑端工具

`friction_profiles.py` 保存、检查、导出和导入三轮完整参数。文件放在电脑上；导入只修改板端 RAM，重启仍恢复编译时默认值。当前没有连接板端 Flash。

它不发送启动或停止命令。导入需要电机已经处于停止状态，由固件在提交和实际生效时检查。运行中可以只读导出。

## 现在没有硬件也能做的事

在工程根目录执行，Python 3.10 及以上即可，不需要第三方包：

```powershell
python tools/friction_profiles.py example profiles/example.json
python tools/friction_profiles.py validate profiles/example.json
python tests/parameters/test_profiles.py
```

示例包含斜坡 300 rpm/s，每轮 Kp=0.5、Ki=0.1、Kd=0、电流限幅 1500。这只是格式示例，不能视为已经适合实物的参数。

文件存在时默认拒绝覆盖；确实需要替换时加 `--force`。输出先写同目录临时文件并刷新，再通过替换发布完整文件。新文件名用独占创建预留；异常会清理预留和临时文件，若电脑在写入中断电，可能留下空预留文件，下次检查会拒绝它。替换已有文件需要 `--force`。

## 后面接硬件的操作

先在板端适配 VOFA 调试串口，并启用 `BENCH_ENABLE_VOFA`、`BENCH_ENABLE_PARAMETERS`。此工具连接的是 **VOFA 二进制调试串口**，不能连接输出 `[yaw]` 等文字的 USB CDC 诊断端口。串口编号和波特率以实际接线、板端配置为准。

仅实时通信需要额外安装：

```powershell
python -m pip install pyserial
```

以下 `COM7` 只是写法示例，执行前换成用户确定的端口。工具不会自动选择串口，也不会自动重连。运行工具期间关闭占用同一串口的 VOFA 或其他终端；一次只能有一个命令发送者。

```powershell
python tools/friction_profiles.py export profiles/tuned.json --port COM7 --baud 115200
python tools/friction_profiles.py validate profiles/tuned.json
python tools/friction_profiles.py import profiles/tuned.json --port COM7 --baud 115200
```

导出读取一次冻结的完整参数快照，即使控制任务随后又修改参数，文件也不会混入新旧字段。文件记录快照修订号和编译时电流上限，便于追踪来源。

导入按下面的步骤进行：

1. 校验电脑文件的格式、单位、字段、数值范围和 CRC。
2. 读取板端当前参数与各轮编译时电流上限，提前检查限幅。
3. 开始一个事务，逐项暂存全部 13 个值；此时不会改变实际控制参数。
4. 发送一次提交。板端检查停止状态、完整性、CRC、参数范围及从开始事务以来参数是否改变。
5. 等待板端明确报告 `APPLIED`，再读取一个新的完整快照，确认实际值和 CRC 与文件一致。

只有最后一步通过，工具才报告“已应用到 RAM 并读回”。`QUEUED` 只表示排队，电脑文件已保存也不代表板端已生效。工具从不把上述步骤描述为“Flash 已保存”。

默认每条命令等待回执不超过 3 秒，可用 `--timeout 0.1..10` 设置。板端冻结快照和导入事务有 30 秒总租约，不能靠不断查询续期。发送周期很慢或通信拥堵时可能无法在租约内完成；工具报错，不自动延长板端租约。

## 遇到错误如何处理

| 提示 | 含义与处理 |
| --- | --- |
| `requires stopped motors` / `BUSY` | 尚未停止、已有其他参数事务，或者参数状态发生变化。先通过正常控制接口停止电机并检查状态，再重新开始导入；工具不会替你发送 STOP。 |
| `exceeds compiled board cap` | 文件的电流限幅超过该轮编译时上限。不能通过导入绕过上限。 |
| `no valid 44-channel VOFA stream` | 检查端口、波特率、功能开关和板端串口适配；也可能误接了 USB 文本诊断口。 |
| `CRC mismatch` | 文件被改动、数据损坏或快照读取异常；拒绝继续导入/发布导出文件。 |
| `UNAVAILABLE` | 检查参数功能是否关闭，或固件相关配置是否可用。 |
| `COMMIT ... unconfirmed` | 提交回执丢失，无法判断是否生效。不要将此当作明确失败后立即重发。先查询/导出当前参数、查看板端状态。 |
| `queued, but APPLIED was not confirmed` | 只确认排队，未确认控制任务应用完成。检查板端诊断和当前参数。 |
| `APPLIED ... readback differs` | 板端报告应用，但读回数据与目标不一致，不能报告导入成功。检查其他调参来源和通信。 |

工具不会自动重试 COMMIT，也不在异常后猜测性地重发整组参数。提交前出错时，暂存事务可能仍占用板端；从 BEGIN 起最多 30 秒后由固件轮询过期。协议提供显式 `IMPORT_ABORT` 给需要它的上位机，当前命令行工具不自动发送 ABORT。提交后已排队的事务不能靠 ABORT 撤回。

## 参数范围与单位

共 13 个字段；F1、F2、F3 编号不随模块开关重新排列。

| 文件字段 | 范围 | 单位/含义 |
| --- | --- | --- |
| `ramp_rpm_s` | 1..2000 | 电机转子 rpm/s |
| `f1_kp`、`f2_kp`、`f3_kp` | 0..100 | PID 误差采用电机转子 deg/s |
| `f1_ki`、`f2_ki`、`f3_ki` | 0..1000 | 积分时间单位为秒 |
| `f1_kd`、`f2_kd`、`f3_kd` | 0..1 | 微分时间单位为秒 |
| `f1_current_limit`、`f2_current_limit`、`f3_current_limit` | 文件通用范围 1..16384 | C620 原始电流量，不是安培；板端还检查各轮编译时上限 |

这是输入校验范围，不是推荐调参范围。数字编码为 IEEE754 float32，拒绝 NaN、Infinity、超范围和非零下溢。JSON 小数会明确转换成 float32 后计算 CRC，例如 `0.1` 会保存为固件实际表示值。

不保存使能状态、运行目标、CAN ID、方向、最大转速或硬件绑定。导入不能扩大编译时硬件限制，也不能启动电机。

## 文件和通信约定

JSON 顶层必须包含 `format`、`schema`、`version`、`units`、`values`、`crc32`，只允许额外的 `source` 来源对象；重复键和未知键会被拒绝。`units` 包含固定单位代码 1 及显式文字映射，不能将 deg/s 改写为 rpm。

来源对象记录 `revision`、`active_motor_mask`、`current_caps`，仅作信息，不参与参数 CRC。文件大小限制为 16 KiB。校验不能替代实机电机身份和安装确认。

CRC 使用 IEEE CRC32（Python `zlib.crc32`），计算对象是以下二进制记录的前 68 字节，与 JSON 空白、缩进或键顺序无关：

| 字节位置 | 内容 |
| --- | --- |
| 0..3 | ASCII `FRP1` |
| 4..5、6..7、8..9、10..11 | u16 小端：schema=1、version=1、units=1、count=13 |
| 12..15 | u32 小端保留字段，必须为 0 |
| 16..67 | 13 个 float32 小端：斜坡，然后 F1/F2/F3 各自 Kp、Ki、Kd、电流限幅 |
| 68..71 | 前 68 字节的 CRC32，小端 |

默认示例的 CRC 为 `8a516eab`。跨语言测试向量：斜坡 300，每轮 `(1,2,0,1500)`，CRC 为 `77ac2132`。

手改文件数值会使原 CRC 失效。正常工作流程是通过现有调参接口调好后导出。离线代码生成新配置时，可以调用 `Profile(values)` 和 `save_profile(path, profile)`，由同一校验和编码流程生成新文件；不要只绕过 CRC 检查。

线上命令仍为 ASCII `get seq id` / `call seq op args...`，每次请求使用新的 1..65535 序号，BEGIN 的序号作为整个暂存事务的 token。

| 操作 | 含义 |
| --- | --- |
| call 10 | 冻结参数快照 |
| call 11 | BEGIN：schema、version、units、count、CRC 低 16 位、高 16 位 |
| call 12 | FIELD：token、索引 0..12、值 |
| call 13 | COMMIT：token；成功回执必须是 QUEUED |
| call 14 | ABORT：token，仅可取消 STAGING，当前工具不调用 |
| get 100..107 | 冻结快照元信息、CRC 和修订号 |
| get 108 | 当前导入状态：0空闲、1暂存、2排队、3已应用、4失败 |
| get 109 | 板端持久存储可用状态；当前为 0 |
| get 110、111..113 | 活动轮掩码、各轮编译时电流上限 |
| get 114..115 | 当前参数修订号低/高 16 位 |
| get 200..212 | 冻结快照的 13 个字段 |

`get 114` 和 `get 115` 是两次独立的实时读取，两次之间参数可能改变，不能直接将它们拼接后当作一致的修订号。需要一致版本时先 SNAPSHOT，再读取冻结的 `get 106/107`；本工具采用后者。

回执来自固定 44 通道、180 字节的 JustFloat 波形帧。工具先清理电脑接收缓冲，再观察当前回执选择下一个序号；建立/恢复字节对齐需要连续两帧，之后按固定长度解码。它检查有限数值和回执字段，并同时匹配序号与 ID，不以第一次遇到帧尾字节就切帧。

JustFloat 帧自身没有 CRC；上述帧检查无法检测所有仍然是有限数值的位翻转。完整参数的 CRC 和提交后再次读回承担参数一致性检查。此协议面向独占的实验室串口，不提供身份认证。

## 离线测试边界

测试覆盖 JSON/单位/版本/CRC 拒绝、float32 边界、文件替换失败、噪声/截断/帧内伪帧尾、序号回绕、错误回执、超时、编译时电流上限、完整暂存/单次提交、只排队未应用及应用后读回不一致。

串口测试使用内存中的模拟板端，不打开串口，不证明实际波特率、UART 队列、实时性能或摩擦轮控制效果。
